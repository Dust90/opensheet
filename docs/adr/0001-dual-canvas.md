# ADR-0001: 双 Canvas 渲染（Content + Overlay）+ DOM 编辑器层

## 状态

已接受（M0 决策，M1 实现）

## 背景

表格渲染需要在数据变更（低频、大范围）与选区/悬停变化（高频、小范围）之间解耦重绘成本。候选方案：单 Canvas 分阶段绘制；多 Canvas 分层。

## 决策

采用**双 Canvas**：

- **Content Canvas**（下层）：背景、网格线、行列标题、单元格文字与底色。仅按 Dirty Region 局部重绘。
- **Overlay Canvas**（上层）：选区填充、活动单元格框、填充柄、冻结分割线、列宽拖拽线。选区变化时整视口重绘（<1ms）。
- **DOM 层**：单元格编辑器、上下文菜单、拖拽把手。

两层均按 `devicePixelRatio` 设置物理尺寸并 `setTransform(ratio, …)`，滚动时严格同步 transform。

## 理由

- 选区拖动是 60fps 高频操作，与内容重绘解耦后 Content 层可保持缓存。
- 双 Canvas 比对每个图层单独 Canvas 合成开销低，且冻结四段裁剪只需实现两次而非五次。

## 后果

- 滚动同步、DPR 缩放、冻结线贯穿两层是 M1 的主要复杂度来源。
- 若 M6 性能报告证明两层仍不足，可演进为三 Canvas（冻结区独立一层），接口预留。
